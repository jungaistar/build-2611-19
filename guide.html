사용법

프로토콜과 HCESPN 을 등록하면 RAW DATA 를 자동으로 풉니다

프로토콜 관리 → HCESPN 관리 → RAW DATA 해석 순서입니다. 새 HCESPN 이 생겨도 등록만 하면 되고, 등록정보는 이 브라우저에 쌓입니다.

Bit 단위 필드(19번에서 추가)

한 Byte 를 Bit 몇 개씩 나눠 쓰는 필드를 Byte 필드와 함께 등록합니다.

  • 적는 법 — S.P 를 「52.1」(Byte 52 의 Bit 1), Length 를 「2 bits」로 적습니다. 「52.1」은 소수가 아닙니다. Byte 필드는 예전처럼 「2-7」「6 bytes」.
  • Bit 번호 기준 — 프로토콜마다 「Bit 1 = LSB」 또는 「Bit 1 = MSB」를 고릅니다. Bit 필드가 있는데 고르지 않으면 저장 · 해석하지 않습니다(추정하지 않습니다).
  • 겹침 — 같은 Byte 에 필드가 여럿이어도 Bit 범위가 겹치지 않으면 됩니다. 비어 있는 Bit 는 알려 줍니다.
  • Byte 경계 — 한 Byte 안(시작 Bit + 길이 − 1 ≤ 8)에서만 정의합니다. 넘으면 오류입니다.
  • 해석 — 꺼낸 값에 HCESPN 의 열거값 · 환산식을 적용합니다. HCESPN 이 등록돼 있지 않으면 추출한 RAW 값만 보여 줍니다.
  • 확인 — 결과표의 「Bit 범위」「추출 RAW」 열, Byte Viewer 에서 점선 테두리 Byte 에 마우스를 올리면 그 Byte 의 필드와 Bit 범위가 그림으로 보입니다.
  • 검증 예시 — Bit 1 = LSB 일 때 0xB6 은 Bit 1–2 = 2, Bit 3–4 = 1, Bit 5–8 = 11 / 0xA5 는 Bit 1–4 = 5. 「예시 데이터 넣기」의 세 번째 줄(E1 B6 A5)로 볼 수 있습니다.

먼저 — 예시로 한 바퀴

처음 열면 기획서에 실린 예시(프로토콜 A1 · B1, HCESPN 16 · 90 · 127 · 128)가 들어 있습니다. 「RAW DATA 해석」에서 예시 데이터 넣기 → 해석하기를 누르고, 위쪽 Byte 칸에 마우스를 올려 보세요.

실제 정의를 넣기 전에 대시보드의 「예시 지우기」로 비울 수 있습니다. 예전 판(프로토콜 정의 표 한 장으로 해석하던 v1.0)은 왼쪽 아래 「예전 판(v1.0)」에 그대로 있습니다.

1. 프로토콜 관리

  1. 「프로토콜 등록」을 누르고 이름 · 발신자(MCU · RMCU · 인증장치, 직접 입력 가능) · 수신자 · 버전을 넣습니다.
  2. 원본 문서(엑셀 등)에서 프로토콜 표를 끌어 복사해 「프로토콜 표 붙여넣기」 칸에 붙이고 표로 읽기를 누릅니다.
  3. 읽은 결과가 아래 Byte Mapping 표에 들어갑니다. 틀린 곳을 고치고 저장합니다.

자동 검증

  • 필수 열 누락, Start Position 겹침, 정의되지 않은 빈 구간, HCESPN 미등록, 같은 발신자 · Message Type · 버전 중복.
  • S.P 범위와 Length 가 맞지 않으면 고치지 않고 그 줄에 알립니다(예: 8-51 인데 24 bytes). 원본 사양을 확인해 직접 고쳐 주세요.
  • 프로토콜의 Length 와 HCESPN 의 Data Length 가 다르면 그 항목은 환산하지 않습니다.

버전

이미 저장한 프로토콜을 고칠 때 버전 칸의 값을 바꾸고 새 버전으로 저장을 누르면 이전 버전이 보관됩니다. 「이전 버전」을 켜면 목록에 보이고, 해석 화면에서 버전을 골라 과거 RAW DATA 를 이전 버전으로 다시 풀 수 있습니다.

2. HCESPN 관리

  1. 원문 붙여넣기 — HCESPN 문서에서 해당 번호 부분을 복사해 붙입니다.
  2. 자동 구조화 — 번호 · 이름 · Data Length · Byte 별 항목 · Resolution · Offset · 유효범위 · 특수조건을 찾아 칸에 넣습니다.
  3. 확인 및 수정 — 문서마다 표현이 달라 잘못 읽을 수 있습니다. 반드시 확인합니다.
  4. 저장

특수조건

「byte4 = 0xFF 이면 Not available」 같은 조건입니다. 적용 범위를 「하위 필드마다」 또는 「이 HCESPN 전체」로 정해야 적용됩니다. 원문을 읽어 들였을 때는 「확인 필요(적용 안 함)」로 두고, 해석 화면에 적용하지 않았다고 알립니다. 원본 사양을 확인한 뒤 범위를 골라 주세요.

3. RAW DATA 해석

  • 직접 입력 — HEX 를 붙여 넣습니다. 여러 건이면 한 줄에 하나씩. 공백 · 줄바꿈 · 0x · 소문자는 자동으로 정리합니다.
  • Excel 업로드 — 1열 데이터 수신일자, 2열 수신 시간, 3열 메시지(16진수). 일부 행이 오류여도 나머지는 계속 분석합니다.
  • 첫 Byte 의 Message Type 으로 프로토콜을 찾습니다. 같은 Type 이 여러 발신자에 있으면 발신자를 고르고, 버전이 여럿이면 가장 높은 버전으로 풀고 버전을 고르게 합니다.
  • RAW DATA Viewer — Byte 마다 한 칸, Parameter 마다 색이 다릅니다. Byte 에 마우스를 올리면 Byte 위치 · RAW · Parameter · HCESPN · 환산식 · 해석 결과 · 검증 결과가 뜨고, 같은 값에 속한 Byte 가 함께 강조됩니다.
  • 상세 해석 결과표와 Excel 다운로드(메시지요약 · 해석결과).

자료 보관

  • 프로토콜 · HCESPN · 분석 이력은 이 PC 의 이 브라우저에만 저장됩니다. 창을 닫아도 남지만, 브라우저의 사이트 데이터를 지우면 함께 지워집니다.
  • 대시보드의 백업 내려받기(JSON)로 받아 두고, 다른 PC 에서는 「백업 불러오기」로 옮깁니다.
  • 여러 사람이 같은 등록정보를 함께 쓰려면 서버 DB 가 필요합니다. 저장 구조는 표 모양 그대로 두어 옮기기 쉽게 했습니다(기획서 「데이터」 참고).
