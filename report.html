3. 기능과 시험

기획서의 기능 6가지와 시험 154개입니다.

기능내용
Bit 단위 필드「52.1 / 2 bits」처럼 한 Byte 안의 Bit 몇 개를 필드로 등록하고 해석합니다.
Bit 범위 검증같은 Byte 의 필드가 겹치는지 실제 Bit 범위로 확인하고, 비어 있는 Bit 를 알려 줍니다.
Bit 번호 기준Bit 1 이 LSB 인지 MSB 인지 프로토콜마다 정합니다. 정하지 않으면 해석하지 않습니다.
대시보드등록 현황, 미등록 HCESPN, 최근 분석 이력 · 다시 해석, 백업.
프로토콜 관리표 붙여넣기 등록, Byte Mapping 편집, 자동 검증, 버전 보관.
HCESPN 관리원문 자동 구조화, Type · 하위 필드 · 환산식 · 특수조건, 버전.

6. 한계와 남은 일

  • Byte 경계를 넘는 Bit 필드(예: Bit 7 부터 4 bits)는 지원하지 않습니다. 필요한 경우 두 필드로 나눠 정의해야 합니다.
  • HCESPN 820 · 822 · 823 · 824 의 뜻은 받지 못해 등록하지 않았습니다 — 예시에서는 추출한 RAW 값만 나옵니다. 「HCESPN 관리」에서 열거값을 등록하면 뜻이 붙습니다.
  • 날짜 · 배열 형식의 HCESPN 은 Bit 필드에 쓸 수 없습니다.
  • 자료는 이 브라우저에만 저장됩니다. 09번에 등록해 둔 자료는 자동으로 넘어오지 않습니다(09번에서 백업 → 19번에서 불러오기).
  • 업무 자료는 지금처럼 브라우저 안에서만 처리합니다. 로그인 DB 에는 「누가 쓸 수 있는가」와 게시판 글만 있습니다.
  • 로그인 뒤 화면(게시판 · 관리 · 첫 화면 고르기)은 실제 계정으로 눌러 보지 않았습니다. 가입 → 사용 신청 → 승인 → 게시판 글쓰기 확인은 기획자와 관리자 몫입니다.
  • 독립 운영까지 남은 것: 본인 Supabase 프로젝트에 auth.sql · board.sql · site.sql 실행 → js/auth-config.js 의 url · anonKey 교체 → 다시 배포(supabase/README.md)
